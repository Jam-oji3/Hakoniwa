# ハコニワ 実装ロードマップと確認項目

> 本書は [DESIGN.md](DESIGN.md) の初期リリース要件を、実装順・検証方法・完了条件に分解した実行計画です。
>
> 方針: UIより先にDomainを確立し、代表シナリオ（ハンマー形状）を縦に貫く最小実装を早期に完成させる。各フェーズは、次のフェーズを安全に始められる確認が済んでから進める。

## 1. 実装の原則

- **Domainを唯一の正とする。** egui、wgpu、PDF、ファイルI/OはDomainの状態を直接書き換えない。
- **操作はCommandに集約する。** すべての編集操作はUndo／Redo可能なApplication Commandとして扱う。
- **Pieceの単一平面制約を境界で検証する。** 不正なPieceを作成・読込・出力できないようにする。
- **小さく縦に完成させる。** 3D編集、Piece化、保存、PDF、構造警告を、まずハンマーの最小シナリオで一巡させる。
- **自動分割は初期版に入れない。** 手動選択・選択面・XY/XZ/YZ平面によるPiece化に限定する。
- **構造チェックは注意喚起である。** 「安全を保証する」表現・判定にはしない。
- **仕様は必要になる実装フェーズで`docs/`に追加する。** 未実装機能の詳細仕様を先回りして固定せず、実装に着手する前に、その機能のデータ形式・入出力・エラー方針を文書化する。

## 3. 詳細実装計画

### M0: 基盤・品質設定

#### 実装すること

1. Cargoワークスペースを作り、責務ごとに最低限のクレートを分ける。
   - `hakoniwa-domain`: エンティティ、値オブジェクト、検証、解析規則
   - `hakoniwa-application`: Command、Undo/Redo、ユースケース
   - `hakoniwa-infrastructure`: `.ibcad`、PDF、パレット
   - `hakoniwa-presentation`: eframe/egui、wgpu描画、画面状態
   - `hakoniwa-app`: Windows向け実行ファイル
2. `rustfmt`、`clippy`、単体テストをローカルとCIで実行する。
3. エラー型、ログ方針、ID生成方針（UUID等）を決める。
4. ハンマー形状の小さな固定フィクスチャをテスト用に用意する。

#### 確認項目

- [x] `cargo fmt --check` が成功する。
- [x] `cargo clippy --workspace -- -D warnings` が成功する。
- [x] `cargo test --workspace` が成功する。
- [x] `hakoniwa-domain` がegui、wgpu、PDF、ZIP、OS APIに依存していない。
- [x] 空のアプリがWindows 11で起動・終了できる。

#### 完了条件

新規開発者がクローン後に上記の検査を実行でき、空のウィンドウを起動できる。

### M1: Domainモデルと不変条件

#### 実装すること

1. 値オブジェクトを定義する。
   - 格子座標、ローカル座標、直交姿勢（XY/XZ/YZ）、色、寸法、安定ID
2. Entityを定義する。
   - `Project`、`Assembly`、`Shape`、`Piece`、`Bead`、グループ階層
3. `Piece`の不変条件を実装する。
   - すべてのBeadが一つのローカル平面にある。
   - 姿勢はXY/XZ/YZのみで、任意角度を持たない。
4. ShapeとPieceの共通操作に必要な属性を定義する。
   - 名前、表示、選択対象、変換、親子関係
5. 出力可能性を判定するルールを実装する。
   - Assemblyに未分割のShapeが残れば、理由と対象IDを返す。

#### 確認項目

- [x] 空のProjectを作成できる。
- [x] 正しい平面Pieceを作成できる。
- [x] 平面外のBeadを含むPiece生成・更新が明示的なエラーになる。
- [x] Shapeを含むAssemblyが「出力不可」と判定され、対象Shapeを特定できる。
- [x] PieceのみのAssemblyが「出力可能」と判定される。
- [x] 座標・姿勢・色・IDの比較とシリアライズ用表現が決定的である。

#### 完了条件

UIなしで、Piece-firstとShape-firstの中間状態を正しく表現・検証できる。

### M2: Application CommandとUndo/Redo

#### 実装すること

1. Command実行器と履歴スタックを実装する。
2. 最初のCommandを追加する。
   - Project/Group/Shape/Pieceの作成・削除
   - Beadの配置・削除・色変更
   - Objectの移動・直交回転・表示変更
   - 階層変更
3. Commandは、成功時のみ履歴に積み、失敗時はProjectを変更しない。
4. Dirty regionの入力となる変更セット（変更Piece、近傍座標）を返す。

#### 確認項目

- [x] Beadを追加してUndoすると完全に元へ戻る。
- [x] RedoでUndo前と同じ状態に戻る。
- [x] 色変更、削除、移動、Piece化後も同様に往復できる。
- [x] 失敗するCommandは履歴も状態も変更しない。
- [x] Undo後に別Commandを実行するとRedo履歴が破棄される。
- [x] 一連のCommand後のProjectを再構築しても同じ状態になる。

#### 完了条件

すべての編集入口がCommand経由であり、代表操作のUndo/Redo回帰テストがある。

4. 形式バージョンと読込時のエラー表示を設計する。

### M9: 接合推定と構造チェック

#### 実装すること

1. Pieceの相対配置・ボクセル形状から接触候補を検出する。
2. 接合候補について、接触面積、嵌合深さ、支持方向を算出する。
3. 初期の警告規則を実装する。
   - 浅い嵌合、小さい接触面積
   - 1マス凹凸だけに依存する大きな接合
   - 支持されない張り出し、重心に対する支持不足
   - 大きな平面Pieceのたわみリスク
   - 固定方向の不足
4. 警告に該当座標・理由・改善方針を持たせ、3Dで強調表示する。
5. 閾値を設定可能なStrategyとして切り出す。

#### 確認項目

- [ ] 接触していないPiece間に接合候補が出ない。
- [ ] 直交して接するPieceから接合候補が作られる。
- [ ] ハンマーの柄を浅く差し込んだケースで浅い嵌合警告が出る。
- [ ] 柄を十分に差し込んだケースで同警告が解消または弱まる。
- [ ] 警告を選ぶと3Dの該当箇所を特定できる。
- [ ] 警告は「保証ではない」とUI/PDFで明確に表記される。
- [ ] 閾値変更の単体テストがある。

#### 完了条件

## 4. 代表受入シナリオ: ハンマー形状

このシナリオは、各マイルストーンを横断する最優先の統合試験とする。

1. 頭部と柄を別Pieceとして作成する（Piece-first）。
2. 頭部・柄をAssemblyに配置し、柄を浅く差し込む。
3. 色別ビーズ数をProject全体で確認する。
4. 接合候補と浅い嵌合の警告を確認する。
5. 頭部と柄を含むPDFを出力し、Piece別図案・集計・組立図を確認する。
6. 柄の差し込みを深くし、警告が改善することを確認する。
7. 保存、終了、読込後に同じ結果を得る。
8. 同じ形をShape-firstでも作り、手動または平面分割でPiece群へ変換して同じ出力を行う。

## 5. 各変更で行う共通確認

- [x] Domainの変更には、正常系・境界値・不正入力の単体テストがある。
- [x] Command追加時はUndo/Redoの往復テストがある。
- [x] 保存形式変更時は旧形式の扱いと読込エラーを確認する。
- [ ] 描画変更時は選択・非表示・分離表示・カメラ操作を確認する。
- [ ] PDF変更時は実ファイルを目視確認する。
- [ ] パフォーマンスに影響する変更時は、代表作品と29×29超Pieceで操作感を確認する。
- [ ] ユーザーに見える警告は、対象箇所・理由・改善方向を必ず含む。
- [x] `cargo fmt --check`、`cargo clippy --workspace -- -D warnings`、`cargo test --workspace` を通す。

## 6. 初期版から除外するもの

- 任意角度のPiece配置
- Shapeの自動分割・最適分割
- 他CAD形式・画像等からのインポート
- モバイル対応
- 実寸ビーズ径・アイロン後変形に基づく厳密な物理保証

これらは初期版の実装を複雑化させないための境界であり、将来追加できるようDomainのStrategy/Repository境界を保つ。

## 7. 実装開始時の最初の小タスク

1. M0のCargoワークスペースと品質コマンドを作る。
2. M1の値オブジェクト（座標、姿勢、色、ID）と`Piece`平面制約をテスト駆動で実装する。
3. 空ProjectへPieceを作成し、Beadを置く最小CommandとUndo/Redoを実装する。
4. M4の最小2Dグリッドから、そのCommandを実行できるようにする。

この順なら、最初の短い開発サイクルで「平面Pieceを作り、ビーズを置き、戻し、保存できる」基盤へ到達できる。
